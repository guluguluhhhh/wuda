2. 共同基础：symmetric allocation + 单调 generation

两个 rank 以相同顺序创建相同形状的 symmetric allocation，并在初始化阶段完成 rendezvous。每个 rank 因而同时持有本地基址和对端基址；热路径只做地址选择，不再分配、不交换指针。

struct SymmetricView {
    uintptr_t local_base;
    uintptr_t remote_base;
    uint32_t rank;

    template <typename T>
    T* local() { return reinterpret_cast<T*>(local_base); }

    template <typename T>
    T* peer_base() { return reinterpret_cast<T*>(remote_base); }

    uint32_t peer_rank() { return rank ^ 1u; }
};
payload: peer direct store signal: signal pad state: monotonic generation
通信signal offsetgeneration作用域
Q gather32 + producer_rank每轮 +1跨 GPU payload 完成
MLA scatter48 + producer_rankpublisher 到达数 / publisher 数跨 GPU FP8/scale 完成
O-proj reduce64 + cta 或 grid slot每 consumer CTA 每轮 +1对端 WoB kernel 已退休

三处都不在 graph replay 前清零 flag。消费者等待 expected 或更大的 generation，避免额外 memset，也避免 host 参与每轮同步。用于性能测试的 rank barrier 只排除 host enqueue 偏差，不属于模型的第四处通信。

3.1 Payload 融在 MQA 尾部的 Query RMSNorm + RoPE

每个 producer rank 都遍历全局 B 个请求和自己的 64 个 head。目标请求属于本 rank 时写本地 symmetric allocation，否则直接写 peer allocation。目标位置包含 producer_rank * 64 的 head 偏移，两个 rank 的写入天然拼成完整 128 heads，不需要后处理拷贝。

const uint32_t owner = batch >= rank0_batch;
const uint32_t owner_row = owner == 0
    ? batch : batch - rank0_batch;
const uint32_t full_head = producer_rank * 64 + input_head;

nv_bfloat16* destination = owner == producer_rank
    ? symmetric_output.local<nv_bfloat16>()
    : symmetric_output.peer_base<nv_bfloat16>();

output = destination
    + (owner_row * 128 + full_head) * head_dim;

通信调度采用 peer-first。Rank 1 的 peer-owned 请求本来就在队列前缀；Rank 0 将自己的 peer-owned 后缀旋转到队首。这样两边都优先发 NVLink store，剩余本地 query 计算可以覆盖传输尾部。

const uint32_t claim_rotate =
    tp2 && producer_rank == 0
        ? rank0_batch * input_heads : 0;
const uint32_t rotated = claim + claim_rotate;
const uint32_t output_row = rotated >= output_rows
    ? rotated - output_rows : rotated;

3.2 同步融在 TopK，不新增通信 kernel

MQA kernel 完成后，同一 stream 启动 TopK。TopK grid 额外带一个 rendezvous CTA；它与真正的 TopK CTA 并行。因为 payload 已在前一个 MQA kernel 中写完，flag thread 本身没有 payload 要 release，当前实现用 volatile system-visible store 发布 generation，然后等待 peer 的 generation，最后做一次 system acquire。

const uint32_t expected = query_generation + 1;

// 写对端 signal pad：宣布本 rank 的 64-head shard 已完成。
asm volatile("st.volatile.global.u32 [%0], %1;"
             :: "l"(peer_flag), "r"(expected) : "memory");

while (load_relaxed_sys(local_peer_flag) < expected)
    spin_pause();

fence_acquire_sys();
query_generation = expected;
先发 peer rows在 MQA 尾部尽早启动跨卡 BF16 写。
继续本地计算剩余 local rows 和 attention 尾部覆盖通信。
TopK CTA 握手通信等待与 TopK 主工作并行。
FlashMLA 消费TopK 返回时，owner buffer 已有完整 128 heads。

这里不是先生成 BF16 再通信。生产 kernel 同时完成 inverse RoPE、FP8 E4M3 量化、UE8M0 scale 生成和 head shard 路由。一个 warp 的 32 lanes 正好覆盖一个 512-byte head，量化结果从寄存器直接以 uint4 写本地或 peer，省掉 shared-memory staging 和第二次读写。

const int destination_rank = source_head / 64;
const int destination_head = source_head % 64;
const bool remote = destination_rank != rank;

uint8_t* fp8_output = remote ? peer_fp8 : local_fp8;
uint32_t* scale_output = remote ? peer_scale : local_scale;

*reinterpret_cast<uint4*>(fp8_address) = packed_fp8;
if (lane == 0)
    remote ? store_peer_u32(scale_address, packed_scale)
           : *scale_address = packed_scale;

4.1 为什么需要两级 release

和 Q 不同，WoA 通过 PDL 与 producer 重叠启动，不能等 producer 整个 kernel 结束。因此必须在 kernel 内证明“所有写 peer 的 CTA 都完成”。CTA parity 被设计成在 task stride 下保持 destination rank 不变，所以恰好一半 CTA 是 remote publisher。

// 每个 remote publisher 用 GPU-scope release 汇入 grid counter。
const uint64_t arrived = atomicAdd_release_gpu(grid_done, 1);

if (arrived % publishers == 0) {
    while (load_acquire_gpu(grid_done) < arrived)
        spin_pause();

    const uint32_t generation = arrived / publishers;
    // 最后一个 publisher 用一次 SYS release 覆盖所有 peer stores。
    store_release_sys(peer_ready + 48 + rank, generation);
}

第一层 atom.release.gpu 把同一 GPU 上多个 publisher CTA 的写聚合到一个 counter；最后一个 publisher 的 acquire 观察完整 join，再用唯一一次 st.release.sys 发布给对端。若每个 CTA 都做 system fence，会把大量并发写强制串行 drain，实测明显更慢。

4.2 WoA 先算本地半边，只在 TMA loader 碰到远端块时等待

dependent WoA 已经通过 PDL 启动。两张卡都重排 M block，使 scheduler 先访问本 rank 已经准备好的 token 半边。只有 TMA load warp 第一次遇到 remote block 时轮询 ready；其余 warp 自然停在既有 pipeline barrier，不增加一套全 kernel 同步。

auto wait_remote_once = [&]() {
    if (remote_ready) return;
    const uint32_t expected = *producer_generation;
    const uint32_t* flag = local_signal + 48 + (rank ^ 1);

    while (load_relaxed_sys(flag) < expected)
        spin_pause();
    fence_acquire_sys();
    remote_ready = true;
};

if (use_remote) wait_remote_once();
tma_copy(use_remote ? remote_desc : local_desc, ...);
关键点：consumer wait 不是 MLA 通信的全部耗时。现在 payload store、publisher grid join、system release 和 WoA remote wait 分属不同阶段；本地 WoA block 可以覆盖前面三项的大部分延迟。

5. 通信三：O-proj partial reduce（TP2 → replicated output）

每个 rank 的 WoB 都计算 [B, 7168] BF16 partial。完整结果是两份 partial 的 BF16 pairwise sum，随后立刻进入 mHC post。这里把 peer publish 融进 WoB epilogue，把 reduce 融进 mHC post，没有单独 all-reduce 或 reduction kernel。

5.1 从同一块 epilogue shared memory 同时写本地和 peer

accumulator 转成 BF16 并落到 epilogue staging buffer 后，128 个 epilogue threads 读取 swizzled tile：一路按原逻辑 TMA store 到普通本地 output；另一路以 16-byte system-scope vector store 直接写 peer 的 symmetric slot。通信没有重新读取本地 output。

for (uint32_t vector = epilogue_thread_idx;
     vector < total_vectors; vector += epilogue_threads) {
    const uint4 bits = *swizzled_smem_vector(vector);
    if (global_m < shape_m) {
        uint4* peer = peer_partial + global_m * hidden + global_n;
        store_relaxed_sys_v4_u32(peer, bits);
    }
}
named_barrier_sync();
tma_store_local_partial(...);

symmetric allocation 预留两个 slot。Rank 0 永远写对端 slot 0，Rank 1 永远写对端 slot 1；consumer 在本地 allocation 中读取“由 peer 写来的 slot”，而自己的 partial 直接读普通 output buffer。

5.2 mHC post 起始 rendezvous

flag 不在 WoB epilogue 内发布，而由同一 stream 中紧随 WoB 的 mHC post kernel 发布。此时前一个 WoB kernel 已完全退休，kernel completion 已覆盖本 rank 的所有 peer stores，因此无需在数百个 epilogue CTA 内各做一次 release fence。每个 mHC CTA 的 thread 0 先和 peer 对齐 generation，再让整个 CTA 开始读 partial。

const uint32_t cta = row * gridDim.x + blockIdx.x;
const bool cta_flags = m * gridDim.x < 256;
const uint32_t next = block_generations[cta] + 1;

if (cta_flags)
    volatile_store(peer_ready + 64 + cta, next);
else if (cta == 0)
    volatile_store(peer_grid_ready, next);

do { ready = volatile_load(local_peer_flag); }
while (cta_flags ? ready != next : ready < next);

block_generations[cta] = next;
__syncthreads();

uint4 sum = add_bf16x8(local_partial, peer_partial);
mhc_mix_and_store(sum, residual, post, comb);

5.3 为什么有两种 flag 粒度

consumer CTA 数策略原因
M × gridDim.x < 256每 CTA 一个 flagCTA 少时，分散 peer flag store 的代价小，避免大量 CTA 争读同一地址。
M × gridDim.x ≥ 256整个 grid 一个 flagCTA 多时只让 CTA 0 发布，减少跨卡 flag store；所有 CTA 等同一完成事实。
这个无显式 release/acquire 的协议依赖一个不可随意改变的边界：payload 必须在前一个 WoB kernel，flag 必须在后一个同 stream kernel。如果把 flag 移回 WoB epilogue，或让两个 kernel 跨 stream 乱序，就必须重新建立覆盖全部 publisher 的 system-scope release/acquire 链。

三处代码不能机械地统一成同一种 fence 模板。真正决定协议的是 flag 发出时 payload 位于哪里：Q 和 O-proj 的 payload 已经过 kernel completion；MLA 为了 producer/consumer overlap，在 producer 尚未退出时就允许 WoA 消费，因此必须显式构造跨 CTA、跨 GPU 的 release 链。

生产代码只保留上述唯一协议，不再携带 runtime communication mode、no-communication workspace、stream-wait 备选协议或 globaltimer 消融埋点。这样不仅减少接口和分支，也避免诊断代码改变 kernel 寄存器、指令和关键路径。

8. 修改时必须守住的正确性边界

约束原因
两个 rank 必须按相同顺序 rendezvous 相同形状的 allocationpeer base 和 signal pad 映射依赖完全一致的 symmetric allocation 顺序。
Q 的 owner 分界固定为 ceil(B/2)它同时决定输出 row、peer-first rotation 和 FlashMLA request ownership。
MLA remote publisher CTA 数必须与 join divisor 一致最后 publisher 的 SYS release 必须覆盖所有 remote stores，少算会提前发布，多算会死等。
WoA 必须先访问本地 M block否则 dependent launch 一开始就等待 peer，MLA/WoA overlap 会退化成串行。
O-proj 的 flag 必须位于 WoB 之后的同一 stream当前最小同步依赖 kernel completion；改变边界必须重新设计内存序。
两个 rank 每轮 graph replay 次数必须一致generation 单调推进；任一 rank 跳轮会让精确 generation 协议失配。
一句话总结：Q 用“提前推送 + 后继 TopK 握手”，MLA 用“producer 内 grid join + WoA 按需等待”，O-proj 用“epilogue 双写 + 后继 mHC rendezvous”。三处都把通信放在已有计算里，但 release 边界根据 producer 是否已经退出而不同。
